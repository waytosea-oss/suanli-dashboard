# Claude 额度自动恢复（2026-09-16）

本次故障来自码表的 OAuth 副本与 Claude 当前登录凭据脱节：旧缓存过期后先尝试续期，限流或失败就提前返回，无法发现新登录。

修复行为：

- 每次到期拉取前，先比较 Claude 本地凭据文件、当前用户默认钥匙串条目与码表缓存；有效的新凭据自动接入，空记录或更旧的记录不覆盖新缓存。
- 钥匙串读取前只检查元数据：必须已解锁，且现有解密 ACL 已信任 `/usr/bin/security`、不要求再次输入密码。条件不满足就跳过，不修改钥匙串授权。通过系统工具的管道读取，不输出令牌。
- 401 即使发生在令牌标称有效期内，也重新同步或续期一次；本轮被拒绝的令牌不再重复使用。
- 新 refresh token 不继承旧 token 的续期失败退避；登录失效后约每两分钟检查一次新凭据。
- 429 尊重 Retry-After（秒数和 HTTP 日期），保存退避时间，重启不会绕过等待。短时故障沿用最近成功额度最多十分钟，之后显示不可用。
- 缓存权限为 0600。账号被服务端撤销时仍需要本人运行 `claude auth login`；完成后不再需要手动运行缓存修复脚本。

覆盖边界：自动钥匙串读取针对当前用户的默认 `Claude Code-credentials` 条目。不枚举其他账号或自定义配置目录的历史条目。钥匙串锁定、访问策略变化、服务端持续限流时不能保证立即恢复。

验证：`TestRunner --filter Claude` 的 18 项测试，包括缓存过期、重新登录、401 恢复、续期轮换、429 跨重启退避、无循环重试、旧数据超时失效。

实机验收：停止旧进程并移走缓存后，新版自动从现有登录重建缓存（0600），无手动注入；码表与小度数据接口均返回 Claude 可用。

## 2026-09-17：独立授权与真实续期验证

第二天复现时，访问令牌已到期，服务端对续期返回 `400 / invalid_grant`。这与单纯的网络失败不同；旧刷新令牌无法靠重试修复。已有证据不能确定旧令牌被谁撤销或消耗，因此不把凭据竞争视为已证实的唯一原因。

为避免码表和日常 Claude Code 共用刷新令牌，新增独立授权入口：运行 `script/claude-dashboard-login.command`。它使用 Application Support 下的独立 `claude-auth` 配置目录登录，完成后写入启用标记；码表读取对应的独立钥匙串条目，并将轮换后的凭据保存在独立缓存。默认 Claude Code 的凭据不被修改。尚未启用独立授权的安装保留原读取方式。

续期请求补齐与本机官方 Claude Code 一致的 scope，超时调整为 30 秒。400 只有明确的 `invalid_grant` 才认定刷新授权失效。失败时保存不含令牌的时间、接口路径、HTTP 状态与 invalidGrant 标记，方便定位无人值守期间的故障。

验证：22 项相关测试通过；另外对独立授权执行了一次真实续期，确认 access token、refresh token 均轮换，轮换结果持久化后额度接口成功返回。这个验证比仅验证登录成功或使用 mock 覆盖更完整，但不能保证服务端永不撤销会话。
